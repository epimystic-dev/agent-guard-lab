# agent-guard-lab research radar - week of 2026-10-25

A short digest of what the frontier shows for runtime guards for autonomous agents this week, followed by what was built and why.

## Signal from the frontier (last 7 days)

1. **GuardFall shell-injection class defeats ten of eleven open-source AI coding agents.** The 2026-06-30 Adversa write-up ([Adversa blog](https://adversa.ai/blog/opensource-ai-coding-agents-shell-injection-vulnerability/), [CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-guardfall-ai-coding-agent-shell-injection/)) that identified GuardFall was re-confirmed by the Cloud Security Alliance in 2026-07 and again referenced in a 2026-10 execution-security survey. The root cause is structural: agents inspect raw command TEXT, but the shell performs quote removal, variable expansion and word splitting AFTER inspection, so a string that looks safe at check time becomes a destructive argv at exec time. The mitigation is well known - `shell=False` with an argv list, allowlist on `argv[0]`, confined cwd, timeout, output cap, no inherited env - and mis-applied again and again across popular agents.

2. **"The Balkanization of Execution-Security Research for AI Coding Agents"** ([arXiv 2607.05743](https://arxiv.org/pdf/2607.05743), 2026-10) - a systematised corpus of 39 execution-security papers (2023-2026) in 17 categories; shell injection, isolation, and TOCTOU are three of the top five failure classes. The paper argues that the current fragmentation of mitigations across isolation research, access control and TOCTOU detection leaves most agents short of a composable primitive set. The practical reading: smaller single-boundary guards, each honest about what they do not prevent, compose better than ambitious frameworks.

3. **Agent Flight Recorder** ([arXiv 2609.01931](https://arxiv.org/abs/2609.01931), 2026-09) - a tamper-evident audit trail for long-horizon tool-using agents. The paper measures approximately 48 microseconds median per-event latency, 512 bytes per event, and 100% detection of edit / delete / reorder / fork tampering with zero false positives using SHA-256 chaining plus Merkle batching plus optional on-chain anchoring. The core primitive (hash-chain + head anchor) is a textbook shape with no vendor-neutral, standard-library implementation at the "smallest honest version" bar.

4. **Tracekit** ([arXiv 2609.35659](https://arxiv.org/abs/2609.35659), 2026-09) - captures intent, reasoning and actions as three separately-chained ledgers with cross-check, specifically for autonomous coding agents. Converges with the Flight Recorder on the hash-chain-plus-sidecar shape; the differentiator is three channels, not the chain. The chain itself is the primitive worth packaging.

5. **"A Black Box for Agentic Processes"** ([arXiv 2609.04017](https://arxiv.org/pdf/2609.04017)) and **aiAuthZ** ([arXiv 2607.05518](https://arxiv.org/pdf/2607.05518)) - two more 2026 papers that use a hash-chained action log (SHA-256, monotonic sequence, verifiable later) as the substrate for every authentication outcome and tool decision. Three independent papers plus one implementation-oriented survey point at the same primitive from different directions.

6. **Hugging Face July 2026 breach post-mortem** ([blog](https://huggingface.co/blog/agent-intrusion-technical-timeline)) reconstructed roughly 17,600 attacker actions from logs over the 2.5 days an autonomous agent was inside the infrastructure. Without a tamper-evident chain, those logs would be only as trustworthy as the host that wrote them. The write-up is the clearest practitioner-side argument for a tamper-evident ledger that this week offered.

7. **MCP tool-poisoning becomes the agentic supply-chain attack of record.** [MCPTox](https://arxiv.org/pdf/2508.14925) (benchmark), the Microsoft [TPA warning](https://thehackernews.com/2026/06/microsoft-warns-poisoned-mcp-tool.html), the Koi Security September 2025 `postmark-mcp` BCC incident, OWASP's addition of "Agentic Supply Chain Vulnerabilities" to the December 2025 Top 10 for Agentic Applications, and Trend Micro's 492-exposed-MCP-server survey all converge on this attack surface. Mitigation requires a per-call content-shape check and an allowlist policy over tool names / descriptors. This is next week's build track; it is distinct enough from `quarantine`'s content-segregation primitive to be a separate project (`toolgate`), not a feature.

8. **AI reasoning-trace leaks** ([Scott Armbruster, 2026-08](https://scottarmbruster.com/articles/encrypted-reasoning-trace-leak-ai-agent-log-security-2026/)) - 182 credentials recovered from 315,320 "encrypted" reasoning blocks on public agent logs. **LiteLLM 1.107.0** ([CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-litellm-1107-gateway-log-token-compromise/), 2026-10) - gateway logs became a credential store. The redaction primitive these two incidents imply (`redact` in the lab charter) is a strong candidate but non-trivial to do world-class in one week; deferred.

## What was built this week, and why

Two world-class, standalone artifacts, both Apache-2.0, zero dependencies, Python 3.9+:

### `saferun` - the smallest honest answer to GuardFall

An argv-allowlisted, shell-free, confined subprocess runner. Ten shape-check rules (`SR-001..SR-010`) covering argv-must-be-list (never `shell=True`), argv[0]-must-be-in-allowlist, no traversal in argv[0], shell-metachars-in-argv flagged for upstream review (narrow set: `| & ; < > $ backtick \n \r`; parentheses, quotes, asterisks, brackets, braces, hash and tilde omitted because they appear routinely in benign non-shell argv elements), workdir-must-exist, env-passthrough-is-INFO (default is a minimal fail-closed env), timeout-must-be-positive, output-cap-must-be-positive, null-bytes-in-later-argv, absolute-path-matched-by-basename. Two entry points: `verify()` returns a `ScanResult` without executing; `run()` fails closed on any HIGH finding with a `RunRefused` carrying the full `ScanResult`. Hard timeout kills the subprocess; output cap either truncates (default) or kills (opt-in). Honest about scope: a permitted command doing permitted destructive things is not prevented; filesystem isolation beyond cwd is not provided; network isolation and memory caps belong to the OS and to the egress / deadman guards. 54 tests pass against the real OS - not mocked.

### `actionlog` - the smallest honest hash-chained ledger

An append-only, SHA-256 hash-chained action audit log. Nine verify-side rules (`AL-001..AL-009`) covering every chain-break class: hash-mismatch (edit), prev-link-broken (insert / delete / reorder), seq-skip, head-mismatch (sidecar disagreement), trailing-garbage, genesis-prev-nonzero, empty-line, malformed-json, missing-field. Each rule maps 1:1 to a `TamperKind` so a caller holding one knows the other. Canonical JSON serialisation (`sort_keys=True, separators=(',', ':'), ensure_ascii=True`) makes byte-wise re-hash stable across platforms. The `.head` sidecar is written atomically after every append so a reader can detect truncation. Thread-safe appends (RLock). Honest about scope: makes tampering visible, not impossible; does not prevent an attacker who holds the current head from forking the chain, does not prevent wholesale deletion, does not substitute for a signed-release or replicated or anchored substrate. 49 tests pass, including a concurrent-append sequence check at 50 threads.

## Belongs elsewhere (noted, not built here)

- **A static linter for MCP tool descriptors (`mcptoolcheck` is already shipped in `epimystic-lab`).** `toolgate` here would be the runtime companion. Deferred one week because the clean split between the two labs' responsibilities deserves a careful design pass; the signal is strong enough that it will likely be next week's primary build.
- **A hash-chained audit substrate at the governance-schema level.** The `auditledger` in `governance-lab` is the governance-document-shaped version; `actionlog` here is the runtime action-shaped version; they compose but are not substitutes.
- **A reproducibility harness for GuardFall or MCP tool-poisoning benchmarks.** Belongs in `repro-lab`.
- **An argv-allowlisted subprocess runner at the OS process level (seccomp / landlock / Windows Job Objects).** Out of scope for standard-library-only; a candidate for a separate project if the OS-isolation shape ever earns its own vendor-neutral primitive.
- **Secret-shaped-string redaction (`redact` in the charter).** Strong signal (LiteLLM 2026-10, reasoning-trace leaks 2026-08) but doing it world-class requires careful false-positive handling of a large regex catalog plus optional entropy fallback. Reserved for a future week.
- **Deadman / effectgate / egressgate / fsguard.** All in the charter, no load-bearing frontier incident this week; deferred to keep the batch at the lab's "world-class or do not ship" bar.

## Discipline notes

- Clean-room throughout: no author's reference code was read for either project; both are independent implementations based on public abstracts, public write-ups, and the Python standard library. Each project's `clean_room` field in `project.json` states the exact sources read.
- Both projects export the lab's shared package surface (`__version__`, `Severity`, `Verdict`, `Finding`, `ScanResult`, `Rule`, `ALL_RULES`) and ship `tests/test_shared_contract.py` with the standard structure.
- Every rule in each project's `ALL_RULES` is documented in that project's README and has at least one firing test.
- The text report in both CLIs renders every non-ASCII character as `<U+XXXX>` and does not crash under `PYTHONIOENCODING=cp1252`; both projects have the explicit regression test.
- Honesty floor on both READMEs: `verified-safe` is never claimed; `origin-valid` (shape within policy) and `self-consistent` (chain matches its sidecar) are the strongest statements made.
- Both projects' tests pass under exactly the CI command declared in `project.json`: `python -m unittest discover -s tests`. No `-t .` flag; no relative imports in test modules; `tests/support` is imported as `from tests import support`.
