# agent-guard-lab research radar - week of 2026-10-18

A short digest of what the frontier shows for runtime guards for autonomous agents this week, followed by what was built and why.

## Signal from the frontier (last 7 days)

1. **OWASP LLM Top 10 for 2026 is now live** - and the shape has changed. **Unbounded Consumption** moved from LLM10 to **LLM06**, up four places, with runaway reasoning loops and unbounded tool calling named as the agent-era face of the risk. Prompt Injection remains **LLM01**, with the indirect form (instructions in ingested external content) called out as the dominant 2026 attack surface. (Imperva and Giskard summaries of the 2026 release; OWASP Gen AI Security Project pages for LLM01 / LLM06.)

2. **"How AI Agents Can Trigger Runaway Costs for Enterprises"** (Dark Reading, 2026) - plain-English pass through OWASP's own agent-tool fan-out simulation. A single poisoned input to an agent can exhaust an inference budget in under an hour. Lists the three primitives that mitigate: token-aware rate limits, hard spending caps, and agent circuit breakers.

3. **Three 2026 arXiv papers on indirect prompt injection converge on content segregation as the core defense primitive.** arXiv 2606.26479 ("Adaptive Evaluation of Out-of-Band Defenses Against Prompt Injection in LLM Agents"), arXiv 2608.27092 ("The Framing Gap: Indirect Prompt-Injection Exfiltration Defeats Surface-Level Defenses in Tool-Using Agents"), and arXiv 2605.11868 ("IPI-proxy: An Intercepting Proxy for Red-Teaming Web-Browsing AI Agents Against Indirect Prompt Injection"). Each proposes different mitigations but all three assume the agent host first establishes a clear boundary between its own instructions and the ingested content; several of the proposed defenses explicitly fail against systems that lack that boundary.

4. **arXiv 2609.22949 ("Beyond Single-Model Injection: A Threat Model and Defense Architecture for Prompt Injection in Multi-Agent Systems")** generalises LLM01 across agent-to-agent handoffs - the same payload crosses N boundaries, and loses provenance each time. The architecture it proposes requires each hop to re-wrap the content with its own provenance tag. The "re-wrap each hop" pattern is what motivates the per-call randomised boundary in `quarantine`.

5. **"LLM unbounded consumption exposes a new cost-control attack surface"** (nhimg.org, 2026) and **"OWASP LLM10: Unbounded Consumption Guide + Checklist"** (aibuzz.blog, 2026) - practitioner-side summaries that stress one point OWASP's own text understates: the mitigations have to be enforced *at runtime by the agent host*, not merely declared in a config. A policy document that caps spend at $5 is not a cap until something refuses the $5.01 call.

6. **arXiv 2606.12737 ("PI-Hunter: Automated Red-Teaming for Exposing and Localizing Prompt Injections")** - the red-team flipside. Automated test harness for prompt injection; implicit in its results is that detection-only defenses are brittle, and content-segregation plus least-privilege compose better than either alone.

## What was built this week, and why

Two world-class, standalone artifacts, both Apache-2.0, zero dependencies, Python 3.9+, matching OWASP's two most-elevated 2026 risks:

### `budgetgov` - the smallest honest OWASP-LLM06 primitive

A runtime budget governor: four caps (**tokens**, **time**, **call-count**, **spend**), a fail-closed reservation protocol (`before_call` / `after_call`), a one-way seal once a cap trips, and an append-only JSONL record of what tripped. Addresses exactly OWASP's recommended trio (token-aware rate limits, hard spending caps, agent circuit breakers) and the Dark Reading point that the cap has to be enforced, not declared. Honest about scope: it is not a pricing oracle, not a token counter, not an audit substrate (compose it with a hash-chained ledger if that is what you need).

### `quarantine` - the smallest honest OWASP-LLM01 content-segregation primitive

A provenance-wrapping and heuristic-neutralising library for untrusted ingested text. Boundary markers are 96-bit per-call random tokens, so an attacker in the content cannot forge a closer. Twelve rules neutralise the recurring injection carriers: Plane 14 TAG characters, bidi overrides, zero-width characters, C0/C1 controls, private-use codepoints, "ignore all previous instructions" variants, role-switch openings, hidden HTML comments, injected `system:` prefixes, pretend-tool-call JSON, over-length runs, and "disregard your system prompt" variants. Every neutralisation leaves a **visible, inert marker**; no silent removal. Honest about scope: raises the cost of indirect injection, does not prevent novel attacks or semantic jailbreaks; composes with instruction-hierarchy and output filtering, replaces neither.

## Discipline notes

- Clean-room throughout: no author's reference code was read for either project; both are independent implementations based on public abstracts, OWASP site text, and the Unicode standard.
- `quarantine`'s rules are deliberately conservative and leave visible markers; a caller inspecting `q.hits` can tell true positives from false positives.
- `budgetgov` refuses to invent token / cost estimates; the caller must declare them. The guard enforces the caps the caller declares and makes no claim about what the next call "really" costs.
- Honesty floor on both READMEs: `verified-safe` is never claimed; `origin-valid` and "no rule in the current registry fired" are the strongest statements made.
